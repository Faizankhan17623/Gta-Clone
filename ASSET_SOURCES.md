# Visual asset inventory

All environment, sedan and character geometry introduced by this upgrade is
generated by project JavaScript. There are no newly downloaded model files,
third-party character skins, photographs or paid asset packs in this pass.

| Source | Content | Delivery |
| --- | --- | --- |
| `js/district.js` | Masonry and paving textures, facade components, windows, signs, curbs, markings, trees and street furniture | Procedural Three.js meshes and canvas textures |
| `js/vehicleModel.js` | Sedan hull, glazing, trim, lights, wheels and police variant; clearcoat paint | Procedural Three.js geometry |
| `js/characterModel.js` | Articulated body (capsule limbs, lathed torso), face, hands, shoes, clothing | Procedural Three.js geometry |
| `js/textures.js` | Asphalt and concrete PBR sets - colour + normal + roughness from one noise height field | Generated at load, no files |
| `js/graphics.js` | Procedural sky environment map, film colour-grade LUT | Generated at load, no files |

The realism pass (`visual-realism` branch) added **no** binary texture, model,
HDRI or LUT files. Every new surface and shape is generated in JavaScript at
load time. Three.js is still the only external rendering dependency, loaded via
the import map in `index.html`; the post-processing addons (EffectComposer,
GTAO, SMAA, LUT, bloom) pulled from that same pinned Three.js version are new
imports but not new packages.

Three.js remains the existing external rendering dependency, loaded through
the import map in `index.html`. Existing project dependencies and their licenses
are unchanged. A GLB importer is unnecessary for these generated models; add one
with an asset license/source record when an external model is actually selected.

This implementation provides greater detail and more natural proportions. It
does not contain scanned photorealistic assets or motion-captured animation.
